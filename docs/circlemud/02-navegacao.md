- Aviso de versão: o DeBo se declara baseado em **CircleMUD 3.0**; este mirror é **3.1**. As linhas citadas valem para *este* código; em um tree 3.0 os números de linha podem diferir (o conteúdo, em quase tudo, é o mesmo). Ver "Limites desta pesquisa".
- Aviso de idioma: todas as strings do engine estão em **inglês**. O DeBo é PT-BR e provavelmente as traduziu; por isso o texto literal de cada mensagem é um fato do **engine**, e a "Como validar" manda conferir a tradução no servidor.

O arquivo [00-afirmacoes-e-validacao.md](00-afirmacoes-e-validacao.md) define níveis extras para evidência de servidor ("Testado (servidor)"); esta pesquisa não fez sessão no DeBo, então nenhuma linha aqui passa de "Testado (código)".

### Definição dos níveis

| Nível | Significa |
| --- | --- |
| **Testado (código)** | O comportamento está no fonte, com `arquivo:linha`. Prova o **engine**, não o DeBo. |
| **Provável** | Decorre do código, mas depende de configuração, versão, tradução ou de o mundo do DeBo ter ou não mudado aquilo. |
| **Dúvida** | Hipótese ou não confirmado. |

## Como usar isto no robô (leitura prática)

1. **Um passo por comando**, e só em `POS_STANDING`. As 6 direções (`n`, `e`, `s`, `w`, `u`, `d`, ou nome completo) são as únicas portas de movimento; `enter`/`leave` só servem para portas com palavra-chave ou para entrar/sair de `ROOM_INDOORS`.
2. **Sucesso** = chegou a tela de uma sala (nome; descrição só se `brief` estiver off no *movimento*, mas `look` explícito sempre descreve). **Recusa** = uma das strings do item 92 e a sala continua a mesma. **Silêncio total** durante luta = comando engolido (item 8).
3. **Movimento** se lê no `score` (`... movement points.`) ou no prompt quando o mostrador `<n>V` estiver ligado. O gasto é a média dos setores e a regeneração é por hora de jogo (~75 s reais).
4. **Identidade da sala** para mortais não tem vnum: usar nome + linha `[ Exits: ... ]` + `exits` (que dá nomes das salas vizinhas) + mobs/objetos.
5. **Portas fechadas somem** da linha de saídas do `look`; se uma saída conhecida do mapa desaparecer do `look`, suspeitar de porta fechada — ou de sala escura, onde o `look` não mostra nada (mas o comando `exits` continua listando direções, com o nome do destino ou `Too dark to tell.`).
6. **Paginação** trava o interpretador: qualquer comando digitado durante o pager vira resposta ao pager. O robô deve reconhecer o prompt `... (n/N) ]` e responder com ENTER (ou `q`) antes de seguir.

## Limites desta pesquisa

- **Versão**: o mirror `master` é **CircleMUD 3.1** (um único commit, `12a0cedb`, de 2012-03-22; sem tags/branch 3.0). O DeBo declara ser baseado em **3.0**. Números de linha de um tree 3.0 puro podem divergir; os comportamentos citados aqui são os do 3.1 oficial.
- **Engine ≠ DeBo**: nada aqui foi verificado no servidor. O DeBo é traduzido (PT-BR), configurado e "fortemente modificado"; portanto *toda* string citada é fato do engine, e a tradução/comportamento real continua a confirmar. Por isso nenhuma linha é "Testado (servidor)".
- **Sem acesso** ao código, aos `.wld`/`.zon`/`.shp` nem à configuração (`config.c` compilada) do DeBo; valores como `tunnel_size`, `holler_move_cost` e pref default de `AUTOEXIT`/`BRIEF`/`COMPACT` podem ter sido mudados (marcados **Provável**).
- **`ROOMFLAGS`, `where` imortal, `ROOM_GODROOM`, `ROOM_DEATH`** só são observáveis com personagem imortal ou em situações perigosas — não recomendo testar `ROOM_DEATH` no DeBo.
- Não medi o **tempo real** da regeneração no DeBo (o item 10 depende de `SECS_PER_MUD_HOUR` compilado); a validação do item 10 é o teste que fecha essa lacuna.
- A página HTML do GitHub foi truncada no `web_fetch`; ela não foi usada. Os arquivos-fonte usados foram baixados por inteiro e cada linha citada foi conferida em cópia local numerada.
